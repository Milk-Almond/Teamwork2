# STUDENT-EDITABLE - Chart Improvement Specialist Instructions

## Specialist purpose

State the agent's bounded responsibility for improving an existing business chart. Make clear that creating the baseline analysis and baseline chart is outside its role.

## Governing question

State the question this specialist asks about the existing visualization and the management communication it must support.

## Source Roles and Authority

- Treat `course_materials/Data_Visualization_for_Business_Decisions_Principles.pdf` as the governing visualization framework. Use its principles to diagnose weaknesses and justify improvements to the supplied chart.
- Treat `course_materials/From_Pixels_to_Insights_Case_Study.pdf` as an illustrative application and calibration source. Use it to understand how the principles can be applied and where human judgment is needed; do not treat it as an additional governing framework or a design template.
- If the two sources appear to conflict, the principles document governs. Explain any consequential conflict and apply the governing principle to the current chart's context.
- Do not copy case-specific titles, colors, annotations, chart types, or other revisions unless the current chart, source data, intended audience, and business question independently justify them.

## Visualization framework the agent must apply

Translate the instructor-supplied visualization principles into explicit diagnostic and design rules. Specify what the agent must inspect, what counts as an important deficiency, and how it should choose among possible improvements. Do not merely paste or summarize the source. Use the case study to calibrate application and human-review needs, not to create additional governing principles.

## Data-fidelity requirements

Specify the checks needed to ensure that the improved chart preserves the source data, units, scales, ordering, categories, time periods, and substantive business answer. State how the agent should respond when the baseline chart conflicts with the data.

## Required chart-improvement behavior

Specify how the agent should handle chart type, comparison structure, hierarchy, titles, labels, annotations, color, clutter, legends, accessibility, and output dimensions when relevant to the supplied principles and case.

## Boundaries and abstention

State what the agent is not authorized to change, what information it must not invent, and when it should request clarification or report that a defensible improvement cannot be completed.

## Testing focus

State the failure patterns that would reveal that the specialist is making only cosmetic changes, distorting data, ignoring the business question, overapplying a principle, or claiming to have produced an artifact it did not create.
